# Railway 24시간 배포 준비

현재 파일은 배포 준비물이며, 서비스 생성/결제/공개 배포 완료를 의미하지 않습니다.

## 서비스 구성

- Dockerfile 기반 단일 서비스, 복제본 **1개**. 같은 DB에 봇 여러 개를 실행하지 않습니다.
- 상시 실행 요금제를 사용하고 유휴 중지/Serverless(절전)를 끕니다.
- 영구 볼륨을 **/data**에 연결합니다. 볼륨 없이 배포하면 재배포 시 경험치가 유실됩니다.
- 서비스 도메인을 생성하고 `PUBLIC_URL`을 그 HTTPS 주소로 설정합니다.
- 환경변수: `DISCORD_TOKEN`, `DISCORD_GUILD_ID`, `DISCORD_CLIENT_ID`, `PUBLIC_URL`.
- 웹 Discord 로그인 사용 시 `DISCORD_CLIENT_SECRET`과 개발자 포털의 `PUBLIC_URL/auth/callback` 등록도 필요합니다.
- 초기 웹 관리자 접속용 `ADMIN_TOKEN`은 강한 난수로 설정합니다. 토큰은 소스에 포함하지 않고 호스팅의 변수 저장소에만 전달합니다.
- Docker 기본값: `HOST=0.0.0.0`, `PORT=8080`, `DB_PATH=/data/bot.db`, `BACKUP_DIR=/data/backups`, `REQUIRE_DISCORD=1`.

## 현재 데이터 이관 순서

1. 계정 연결 후 예상 요금과 서비스/볼륨 구성을 확인합니다.
2. 기존 봇을 종료한 뒤 SQLite 온라인 백업을 만듭니다. 중복 실행 상태로 전환하지 않습니다.
3. 백업을 새 영구 볼륨의 `/data/bot.db`로 이관합니다. 데이터/토큰을 소스 ZIP이나 공개 저장소에 넣지 않습니다.
4. 새 서비스를 실행하고 웹 상태, Discord heartbeat, 명령어 동작을 확인합니다.
5. 새 서버 실패 시 새 서비스를 중지한 뒤 기존 봇을 다시 켭니다.

## 자동 복구

`run.py`는 웹/봇 둘 중 하나가 종료되거나, 시작 3분 후 웹/Discord 상태 확인에 실패하면 종료 코드 1로 나갑니다. Railway의 실패 재시작 정책이 이를 다시 시작합니다. SIGTERM을 받으면 자식 프로세스 둘 다 종료합니다. 일일 SQLite 백업은 영구 볼륨에 보관합니다.

무료 체험 만료/결제 중단/호스팅 장애에서도 무조건 24시간 가동을 보장하는 구성은 아닙니다. 실제 요금은 배포할 계정에서 확인합니다.
