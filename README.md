# ORBIT — 개인 서버용 Discord 활동·경제 봇

경험치를 레벨과 재화로 함께 사용합니다. 구매·선물·베팅으로 경험치가 감소하면 레벨과 보상 역할도 내려갑니다. Python 봇과 웹 관리 서버가 같은 SQLite 데이터베이스를 사용합니다. 유료 플랜이나 여러 서버 관리 기능은 없습니다.

## 구현된 기능

- 채팅·음성 활동 경험치, 제외 채널/카테고리/역할, 쿨타임, 일일 한도
- 일일·연속 출석, 추가 보상, 시간대 설정
- 경험치 기반 레벨, 레벨·출석 보상 역할, 닉네임 레벨 표시, 레벨업 알림
- 누적 경험치·월간 순증감·누적/연속 출석·시즌 순위, Discord 순위 메시지 자동 갱신
- 경험치 지급/회수, 선물과 수수료, 거래 원장, 관리자 변경 이력, CSV 내보내기
- 영구/기간제 역할 상점, 코드 재고 입고·자동 발급, 구매 기록, 만료 역할 회수
- 기존 15종 게임: 홀짝, 주사위, 배스킨31, 스크래치, 슬롯, 돌림판, 지뢰찾기, 하이로우, 블랙잭, 룰렛, 인디언 포커, 틱택토, 폭탄, 타워, 경마
- 추가 3종: 2~6인 텍사스 홀덤, 일일 서버 복권, 채널별 공동 크래시
- 게임별 활성화, 베팅 범위, 수익 수수료, 허용 역할/채널, 제한 시간
- 시즌 수동/자동 종료, 순위 보관, 보상 경험치/역할, 선택적 경험치 초기화
- 채널·역할·활동별 배율 이벤트와 만료
- 웹 관리 화면, Discord OAuth 로그인, 일반 멤버/운영진 권한 분리
- 활동 그래프, 게임별 총 베팅·정산 통계, 실패한 Discord 작업 재시도
- 일일 온라인 DB 백업, 최근 14개 보관

게임 규칙은 웹에 공개됩니다. 이 구현은 공개 기능을 참고한 독립 구현이며 원본 봇과 규칙·확률·UI가 완전히 같지는 않습니다. 기존 대결 게임은 봇 상대이며, 새 텍사스 홀덤은 실제 서버 멤버끼리 대결합니다. 현금 충전·환전은 없습니다.

## 빠른 실행 (Python 3.12 이상)

```bash
cd /workspace/leaderboard
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

`.env`의 `ADMIN_TOKEN`에 충분히 긴 임의의 비밀번호를 입력하고 `DB_PATH`를 실제 프로젝트 경로로 수정합니다. 토큰·비밀키는 채팅이나 Git에 올리지 말고 이 파일에만 입력합니다.

```bash
.venv/bin/python app.py
```

브라우저에서 `http://127.0.0.1:8080`을 열고 **로컬 관리자 연결**에 같은 토큰을 입력합니다. 서버 ID·봇 토큰 없이도 웹 기능, 유저 경험치 조정, 게임과 상점을 사용할 수 있습니다. 역할·알림 작업은 봇 연결 전까지 대기합니다. 테스트 데이터는 실제 사용자 데이터와 구분해 별도 DB_PATH로 실행하세요.

웹과 봇을 한 번에 실행하려면 `.venv/bin/python run.py`를 사용할 수 있습니다. Ctrl+C로 함께 종료합니다. 배포 시에는 systemd 서비스를 권장합니다.

## Discord 연결

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 애플리케이션과 봇을 생성합니다.
2. Bot 설정에서 **Server Members Intent**를 켭니다. 메시지 내용을 읽지 않아 **Message Content Intent는 필요 없습니다**.
3. `.env`에 `DISCORD_TOKEN`, `DISCORD_GUILD_ID`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`를 입력합니다.
4. OAuth2 Redirects에 `PUBLIC_URL/auth/callback`을 등록합니다. 로컬 기본값은 `http://127.0.0.1:8080/auth/callback`입니다.
5. OAuth2 URL Generator에서 `bot`, `applications.commands` 스코프를 선택합니다. 필요한 권한은 View Channels, Send Messages, Embed Links, Read Message History, Manage Roles, Manage Nicknames입니다. Administrator 권한은 필요 없습니다.
6. 봇을 지정 서버에 초대하고, 봇의 역할을 지급·회수할 모든 역할보다 위로 옮깁니다.
7. 웹과 별도 터미널에서 실행합니다.

```bash
.venv/bin/python bot.py
```

서버 소유자와 Discord의 관리자(Administrator) 권한이 켜진 역할을 가진 멤버를 관리자로 인정합니다. 웹 요청과 `/포인트관리` 실행 때 현재 권한을 확인합니다. `/포인트관리`에서 다른 멤버에게 지급·차감하거나 잔액을 설정할 수 있습니다. 변경은 거래 원장과 관리자 기록에 남습니다. 추가로 `ADMIN_USER_IDS`에 등록한 사용자 ID를 봇 관리자로 인정합니다. 예전 관리자 역할 목록은 승인에 사용하지 않습니다.

### 명령어

| 명령어 | 동작 |
|---|---|
| `/출석` | 일일·연속 출석 보상 |
| `/내정보` | 경험치, 레벨, 다음 레벨 필요량 |
| `/랭킹` | 경험치 상위 10명 |
| `/선물 대상 금액` | 멤버에게 경험치 선물 |
| `/게임 종류 베팅 선택` | 15종 게임 시작 |
| `/이어하기` | 진행 중인 게임 버튼 복구 |
| `/상점` | 상품 목록 |
| `/구매 상품번호` | 상품 구매, 코드는 비공개 응답 |
| `/관리` | 웹 사이트 주소 |
| `/홀덤 바이인 빅블라인드` | 2~6인 테이블 생성 |
| `/홀덤보기 테이블` | 테이블 화면 복구 |
| `/복권` | 현재 회차 확인·자동/수동 구매 |
| `/크래시 베팅 자동정산` | 같은 채널의 모집 판에 참여 (0=수동) |
| `/크래시보기` | 해당 채널 진행 화면 복구 |

홀짝 선택은 `odd/even`, 주사위는 `1~6`, 룰렛은 `red/black/zero`, 경마는 `1~5`입니다. 나머지 게임은 선택 인자를 비우고 버튼으로 진행합니다.

## 운영 규칙

- 레벨 = `floor(sqrt(현재 XP / levelBase))`. 베팅금은 게임 시작 시 즉시 차감되고 지급액은 정산 시 반환됩니다. 이때 역할 동기화도 요청됩니다.
- 게임 결과·진행 상태는 DB에 저장합니다. 같은 작업 ID의 재시도는 동일 결과만 반환합니다. 다른 유저의 게임은 조작할 수 없습니다.
- 게임 시간은 시작 시 고정됩니다. **시간 초과는 패배이며 베팅금은 환불하지 않습니다.** 재시작 뒤 `/이어하기` 또는 웹에서 복구할 수 있습니다. 배당·수수료는 시작 시 고정되어 진행 중 설정 변경이 영향을 주지 않습니다.
- 블랙잭은 hit/stand, 소프트17 스탠드, 자연 블랙잭 2.5배입니다. 더블·스플릿·보험은 없습니다. 인디언 포커와 틱택토 등은 봇 상대입니다.
- 순위는 보유 XP 또는 기간 내 순증감 기준이므로 도박·구매·선물이 반영됩니다. 출석 순위는 독립적입니다.
- 음성은 60초 단위로 집계합니다. AFK·봇·설정 제외 대상을 빼고, 양쪽 체크 시점에 참여한 유저에게 지급합니다. 이탈·이동·상태 변경 시 해당 구간은 인정하지 않습니다. 봇이 꺼져 있던 시간은 소급 지급하지 않습니다.
- 활동 통계의 채팅 수는 쿨타임/제외 조건 적용 후 인정된 채팅 수이며 음성 수는 인정된 분입니다. 원문 메시지는 저장하지 않습니다.
- 채팅/음성 일일 한도와 출석 보상은 별도입니다. 배율은 곱해지고 최대 100배입니다.
- 역할 보상에 등록한 역할은 봇이 관리합니다. 다른 자동화와 같은 역할을 공유하지 않는 편이 좋습니다. 최고 역할 모드는 레벨/누적출석/연속출석 각각에서 최고 하나를 지급합니다.
- 시즌 점수는 해당 시즌의 거래 순증감입니다. 시즌 보상과 초기화는 다음 시즌 점수에 포함하지 않습니다. 시즌 경계를 넘긴 게임의 차감/지급은 각각 발생 시점 시즌에 기록됩니다.
- 시즌 보상 역할은 다음 시즌 종료 때 만료됩니다. 다른 상품/보상으로 같은 역할을 보유하면 유지됩니다.
- 코드 상품은 하나의 재고를 한 번만 발급합니다. DM 실패 시에도 구매자의 웹 구매 내역에서 코드를 확인할 수 있습니다.
- Discord 전송/역할 반영은 비동기 작업입니다. 실패 시 운영 기록에서 원인을 확인하고 재시도하세요. 역할은 5분마다 재확인합니다. Discord 전송 직후 프로세스가 중단되는 드문 상황에서는 알림이 중복 전송될 수 있지만 경험치 거래는 중복 적용되지 않습니다.

## VPS 배포

이 앱은 지속 실행되는 Python 프로세스 2개와 로컬 영구 저장소가 필요합니다. 정적 사이트 호스팅이나 Cloudflare Workers에 그대로 올릴 수 없습니다. `deploy/`에 systemd 서비스와 Caddy HTTPS 설정 예제를 제공합니다.

1. Linux 서버에 Python 3.12+, Caddy를 설치합니다.
2. 전용 `orbit` 사용자와 `/opt/orbit` 소스 디렉터리, 쓰기 가능한 `/var/lib/orbit` 데이터 디렉터리를 만듭니다.
3. 소스와 가상환경을 `/opt/orbit`에 두고 `.env` 파일 권한을 `600`으로 지정합니다.
4. `.env`를 다음 경로로 설정합니다.

```dotenv
DB_PATH=/var/lib/orbit/bot.db
BACKUP_DIR=/var/lib/orbit/backups
HOST=127.0.0.1
PORT=8080
PUBLIC_URL=https://실제-도메인
```

5. 서비스 파일을 `/etc/systemd/system/`에 설치하고 웹·봇 서비스를 활성화합니다. 서비스는 각각 한 개씩 실행합니다.
6. Caddyfile의 도메인을 실제 값으로 바꾸고 DNS를 서버로 연결합니다. Caddy가 HTTPS를 처리합니다. 공개 포트는 80/443만 사용하고 8080은 외부에 열지 않습니다.
7. Discord OAuth Redirect도 같은 HTTPS 도메인으로 변경합니다. 운영진 OAuth가 동작하면 필요에 따라 `ADMIN_TOKEN`을 비워 로컬 토큰 로그인을 끌 수 있습니다.

실제 서버·도메인·Discord 자격증명은 포함되지 않습니다. 현재 작업 환경에서 공개 배포하거나 실제 길드에 연결한 상태는 아닙니다.

## 백업 / 복원

웹 서버는 시작 후 및 24시간마다 SQLite online backup으로 일관된 스냅샷을 만듭니다. 파일 권한은 600이며 최근 14개를 보관합니다. 구매 코드가 포함되므로 백업을 공개하지 마세요.

```bash
.venv/bin/python backup.py
```

복원 시 웹·봇을 모두 중지한 뒤 기존 DB와 `-wal`, `-shm` 파일을 별도 보관하고 선택한 백업을 DB_PATH로 복사한 다음 재시작합니다. 백업은 같은 디스크에 있으므로 운영 서버에서는 별도 저장소에도 복제해야 합니다.

## 검증

```bash
.venv/bin/python -m unittest discover -s tests -v
node --check public/app.js
```

브라우저 통합 테스트는 Node.js의 `playwright`와 설치된 Chromium을 사용합니다. `tests/browser.cjs`는 임시 DB/인증 토큰으로 서버를 띄우고 종료합니다.

```bash
node tests/browser.cjs
```

현재 자동 테스트 47개와 데스크톱/모바일 브라우저 흐름 검증이 통과했습니다.

운영 환경에서 Discord 게이트웨이 연결과 명령어 등록, 웹 응답을 확인했습니다. Discord OAuth 로그인은 별도 Client Secret과 리디렉션 설정이 필요합니다. HTTP 인증과 CSRF, 거래·게임·상점·시즌 및 Discord 게임 버튼 흐름은 격리된 데이터베이스로 테스트합니다.

## 추가 게임: 홀덤 · 복권 · 크래시

세 게임 모두 디스코드 텍스트 임베드·버튼·입력창으로 이용합니다. 웹의 **홀덤 · 복권 · 크래시**에서도 참여하고 하단 관리자 설정을 수정할 수 있습니다. 신규 게임은 관리자도 다른 사람 대신 플레이할 수 없습니다. 로컬 관리자 테스트 시 `local-admin` 유저에게 경험치를 먼저 지급하세요.

### 텍사스 홀덤

- 예: `/홀덤 바이인:1000 빅블라인드:20`. 2~6인, 한 핸드씩 진행하는 노리밋 홀덤입니다. 참가비가 아니라 **테이블 칩 예치**이며, 핸드 종료 후 남은 칩+획득 팟을 경험치로 반환합니다. 레이크는 없습니다.
- 기본 모집 120초, 턴 45초. 2명 이상이면 방장이 바로 시작할 수 있고 모집 마감 시 자동 시작합니다. 1명만 있으면 전액 반환합니다.
- 버튼: 참가, 시작, 나가기, 체크, 콜, 레이즈, 올인, 폴드, 내 카드, 새로고침.
- 개인 패는 **내 카드** 버튼을 눌렀을 때 본인에게만 표시됩니다. 공개 테이블 메시지에는 숨겨집니다. 쇼다운 때 폴드하지 않은 참가자만 공개됩니다. 웹 관리자도 다른 참가자의 비공개 패를 볼 수 없습니다.
- 블라인드, 프리플롭/플롭/턴/리버, 7장 중 최선의 5장 판정, 사이드팟, 동일 족보 분할 지급을 지원합니다. 남는 1칩은 딜러 왼쪽부터 시계 방향으로 배분합니다.
- 레이즈 입력은 추가할 금액이 아닌 **이번 베팅 라운드의 총 베팅액**입니다. 최소 레이즈보다 작은 올인은 허용하지만, 이미 행동한 사람의 레이즈 권한을 바로 다시 열지는 않습니다.
- 시간 초과 시 콜할 금액이 없으면 체크, 있으면 폴드합니다. 시작 후에는 임의 환불/퇴장이 불가능하며 자기 차례에 폴드해야 합니다.
- 한 테이블은 한 핸드만 진행합니다. 연속 핸드 테이블, 토너먼트, 리바이는 이번 범위에 포함하지 않습니다.

### 서버 복권

- 기본 가격 100 EXP, 한 회차 1인 최대 20장. **1~20 중 서로 다른 번호 3개**를 선택합니다. 순서는 무관하며 3개 모두 맞으면 당첨입니다 (한 장의 당첨 확률 1/1,140).
- 기본 추첨은 매일 **오후 9시, 서버 시간대 Asia/Seoul 기준**입니다. 설정에서 추첨 시각, 가격, 한도, 판매금 수수료를 변경할 수 있습니다. 이미 열린 회차에는 기존 규칙을 유지합니다.
- 총 판매금에서 해당 회차 수수료를 뺀 금액+이월액을 당첨권 수대로 나눕니다. 같은 사람이 당첨권을 여러 장 가지면 그 수만큼 받습니다. 정수 나머지는 티켓 ID 순서로 분배합니다.
- 당첨권이 없으면 상금을 다음 회차로 이월합니다. 이월금에는 수수료를 다시 떼지 않습니다. 미판매 회차는 이전 이월금을 그대로 유지합니다.
- 모집 종료 후 구매 불가, 자동 선택은 장마다 독립적으로 추첨합니다. 봇/웹이 꺼져 있었다면 재시작 시 밀린 열린 회차를 한 번 처리하고 다음 미래 회차를 만듭니다.
- 추첨 결과는 설정된 순위 게시 채널로 알립니다. 직접 강제 추첨해 결과를 다시 뽑는 기능은 제공하지 않습니다.

### 크래시

- 예: `/크래시 베팅:100 자동정산:2.0`. 20초간 모집하고 같은 채널 참가자들이 하나의 종료 배당을 공유합니다. 모집이 끝나면 추가 베팅은 받지 않습니다.
- 자동 정산은 **1.01~99.99배**, `0`은 수동입니다. 화면은 약 3초마다 갱신되지만 수동 정산은 **서버가 요청을 처리한 시점의 배당**입니다. 메시지에 보이는 지난 배당을 보장하지 않습니다.
- 배당은 시작 후 경과 시간 t초에 대해 `floor(exp(t/8) × 100)/100`. 종료 배당과 같거나 넘으면 패배합니다. 최대 종료 배당은 100배입니다.
- 자동 목표가 종료 배당보다 낮고 목표 시각을 지났다면, 봇이 멈췄다가 재시작해도 목표 배당으로 정확히 한 번 정산합니다. 이후 종료된 판에서 수동 정산을 시도해도 지급되지 않습니다.
- 생성 시 무작위 32바이트 seed의 SHA-256 해시를 공개하고, 종료 후 seed를 공개합니다. 다음 방법으로 종료 배당을 재계산할 수 있습니다.

```python
from social import crash_point
# 종료 메시지에 공개된 seed를 넣으면 정수 단위 1/100배를 반환합니다.
print(crash_point('공개된_seed') / 100)
```

- `h`는 `SHA256(seed + ':crash')`의 처음 13개 16진수 문자(52비트)입니다. 종료값(1/100배 단위)은 `max(100, min(10000, (99 * 2**52) // (2**52 - h)))`입니다. 베팅 접수 전에 확정되며, 진행 중 설정 변경으로 바뀌지 않습니다. 사전 해시 공개는 서버 데이터베이스 자체를 관리하는 운영자의 권한을 제한하는 장치는 아닙니다.

신규 게임은 기존 거래 원장·시즌 순증감·레벨 하락 규칙을 사용합니다. 홀덤 예치 중인 칩과 미추첨 복권·미정산 크래시는 지갑 밖에 있으므로 시즌 초기화 대상으로 차감되지 않고, 이후 반환/당첨은 실제 정산 시점 시즌에 반영됩니다.

Discord `/게임` 시작과 게임 버튼 선택 시 같은 메시지를 게임별 6~12초간 갱신하는 텍스트·이모지 연출이 있습니다. 중간 그림은 장식이며 결과와 별개입니다. 정산 버튼은 즉시 처리됩니다.

## 게임별 Discord 명령어

`/슬롯`, `/홀짝`, `/주사위`, `/룰렛`, `/경마`, `/돌림판`, `/스크래치`, `/블랙잭`, `/인디언포커`, `/하이로우`, `/배스킨31`, `/틱택토`, `/지뢰찾기`, `/폭탄`, `/타워`로 각각 시작합니다. `/게임`은 명령어 안내입니다. 홀짝·룰렛은 선택 메뉴, 주사위·경마는 범위가 제한된 필수 숫자를 받습니다. `/홀덤`, `/복권`, `/크래시`는 기존 별도 명령어를 사용합니다. 진행 중인 게임은 `/이어하기`로 복구하세요.

## 확률·배당 관리

웹 서버 설정 → 게임별 운영 설정에서 홀짝·주사위·슬롯·스크래치·룰렛·경마의 당첨 확률(0~100%)과 원금 포함 당첨 배당(0~1000배)을 변경할 수 있습니다. 비워두면 기본 규칙입니다. 룰렛에서 확률을 지정하면 선택한 색/제로에 대한 당첨 확률로 적용됩니다.

돌림판은 8칸의 가중치와 배당을 입력합니다. 각 칸 확률은 해당 가중치 / 전체 가중치 합이며, 0 가중치는 추첨되지 않습니다. 기본 배당은 0,0,0,0,1,1,2,4입니다.

15종의 승리 수익 배율은 원금을 초과한 수익에만 적용합니다. 예를 들어 기본 반환 2배에 수익 배율 3이면 반환은 4배입니다. 원금 반환·패배에는 적용하지 않습니다. 수수료는 그 이후 수익에 적용합니다. 설정 변경 이력이 남고, 진행 중 게임은 시작 때의 설정을 유지합니다. 홀덤·복권·크래시는 별도 게임 설정을 사용합니다.
